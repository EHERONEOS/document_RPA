## 2. 改造目标

本次改造采用“声明式流程配置 + 船司能力适配器”的混合架构，解决：

1. 船司业务流程调整需要多节点同步代码的问题。
2. 只能停止队列、不能精准停止单个运行中任务的问题。
3. 任务运行过程中没有稳定步骤边界，无法在线断点、修改参数和恢复的问题。

核心原则：

- 流程变化频繁的部分配置化。
- 船司登录、验证码、Shadow DOM、接口监听等复杂能力代码化。
- 流程版本不可变，任务启动时固定版本。
- 新流程先影响新任务，运行中任务默认继续执行原版本。
- 不允许通过流程配置执行任意 Python 代码。
- 现有静态任务路由保留，支持渐进式迁移和失败回退。

## 5. 声明式流程与船司适配器职责

### 5.1 声明式流程负责什么

流程配置负责描述业务编排，不负责实现浏览器底层细节：

- 步骤顺序。
- 条件分支。
- 列表循环。
- 参数映射。
- 字段填写顺序。
- 页面动作组合。
- 超时和重试。
- 步骤级断点开关。
- 业务校验节点。
- 保存、下载和结果回传节点。

流程中的每一步必须拥有稳定的 `stepId`，并能记录输入、输出、耗时、错误和执行结果。

### 5.2 船司适配器负责什么

船司适配器负责网站差异和高复杂度能力：

- 登录、Cookie 复用、MFA 和验证码。
- 页面 URL 和导航策略。
- Shadow DOM 访问。
- 动态选择器和特殊下拉框。
- 网络接口监听。
- 船司页面的字段回读规则。
- 船司特有的提交、保存和幂等判断。
- 船司错误信息到统一任务错误的转换。

适配器对流程引擎暴露能力目录，例如：

```text
MSCGW.login
MSCGW.open_booking
MSCGW.open_shipping_instruction
MSCGW.fill_party
MSCGW.fill_container
MSCGW.fill_cargo
MSCGW.verify_shipping_instruction
MSCGW.save_shipping_instruction
MSCGW.download_preview
```

流程配置只能调用已注册能力，不允许保存任意 Python 表达式、脚本或未审核的代码片段。

### 5.3 MSCGW 迁移映射

| 当前实现 | 目标职责 |
|---|---|
| `MSCGW/router.py` | 队列名映射到 `flowId`，同时保留静态任务回退 |
| `MSCGW/base.py` | MSCGW 能力适配器基类 |
| `common/login.py` | `MSCGW.login` 能力 |
| `selectors.py` | 逻辑控件到真实选择器的映射 |
| `fht_mscgw_si.py` | 过渡期任务实现，逐步拆为能力和步骤 |
| `si_field_verify.py` | SI 专用字段校验能力 |
| `BaseRpaTask` | 浏览器、录屏、截图、OSS 和结果回传运行时 |

迁移期间的路由规则：

```text
队列绑定了 flowId -> 使用 FlowRuntime
队列未绑定 flowId -> 使用当前 Python 静态任务
流程执行失败 -> 按发布策略决定是否允许静态回退，不自动重复提交外部副作用
```

## 6. 流程版本和生效规则

流程生命周期：

```text
草稿 -> Schema 校验 -> 测试 -> 灰度发布 -> 正式发布 -> 下线 / 回滚
```

流程版本至少包含：

- `flowId`、`flowVersion`。
- 客户、船司、业务和队列绑定。
- 适配器名称及适配器版本。
- 步骤定义、变量定义和参数映射。
- 超时、重试和异常策略。
- 可设置断点的步骤列表。
- 配置校验和。
- 创建人、发布人、发布时间和发布备注。

生效规则：

1. 中心发布不可变流程版本。
2. 在线 Agent 收到版本变更事件。
3. Agent 从中心拉取完整流程并校验校验和。
4. Agent 写入本地 `last-known-good` 缓存。
5. 新任务使用最新已缓存版本。
6. 已运行任务继续使用启动时固定的版本。

节点离线时使用最近一次有效缓存，恢复在线后补齐版本。流程定义不通过 Redis 传递完整内容，Redis 只传递版本变更通知和同步命令。

## 7. 任务级终止设计

当前 `QueueSupervisor` 是队列级控制器，不能直接精准结束 Worker 内的单条任务。后续需要引入 `TaskRuntime Registry` 和独立 `TaskExecutor`。

任务注册信息至少包括：

- `taskRunId`。
- `rpaMessageId`。
- 队列、设备和流程版本。
- Worker PID、TaskExecutor PID。
- 浏览器 PID、调试端口和账号租约 ID。
- 当前 `stepId`。
- 任务状态和最近心跳。

终止流程：

1. 中心创建带审计 ID 的 `cancel_task` 命令。
2. Redis Streams 将命令发送到目标设备。
3. Agent 根据 `taskRunId` 定位执行器。
4. 先执行协作式取消。
5. 超过宽限时间仍未退出时，终止对应任务进程组。
6. 关闭对应浏览器并释放账号租约、端口和临时 profile。
7. Worker 独立完成消息确认和取消结果发布。

消息处理语义必须区分：

- 尚未产生外部副作用：允许 NACK 重新入队。
- 已经保存或提交到船司：默认 ACK 并标记 `CANCELLED_UNCERTAIN`。
- 业务动作必须按 `rpaMessageId`、页面状态或接口查询实现幂等。

强终止只能中断本地执行，不能回滚船司网站已经完成的外部操作。

## 8. 在线断点调试设计

断点设置在流程 `stepId`，不设置在 Python 源码行。任务到达断点后暂停，并保存：

- 流程版本和当前步骤。
- 已完成步骤和待执行步骤。
- 脱敏后的输入参数和运行变量。
- 当前页面 URL。
- 页面截图、DOM 摘要和日志地址。
- 浏览器 PID、端口和账号租约。
- 最近一步的输入、输出和异常。

允许修改的内容必须由流程 Schema 明确声明，例如 Booking Number、Container Number、付款方式和未执行步骤参数。

不允许在线修改：

- 密码、Cookie、验证码 Token。
- 已执行步骤的历史结果。
- 未声明的内部对象。
- 任意 Python 代码。

参数修改后需要重新校验，并根据步骤依赖判断是否需要回退到某个 checkpoint。已产生外部副作用的步骤不能无条件重跑。

## 10. Redis Streams 规划

保留现有控制协议，新增事件类型，不改变原有队列命令语义。

新增命令：

- `flow_sync`
- `cancel_task`
- `pause_at_step`
- `patch_task_context`
- `resume_task`

新增事件：

- `flow_sync_result`
- `task_started`
- `task_heartbeat`
- `task_step_changed`
- `task_paused`
- `task_cancelled`
- `task_finished`

所有命令必须具有：

- `commandId`。
- `deviceId`。
- `taskRunId` 或 `flowId`。
- 幂等处理标识。
- 创建时间和超时策略。
